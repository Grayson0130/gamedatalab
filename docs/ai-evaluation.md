# AI 与本地化评估：质量、成本与玩家体验

游戏 AI 应先定义任务和失败成本：语言 QA、内容标注、NPC、客服与分析助手需要不同评测。模型名或排行榜不能代替自己游戏的评测集。

## 本地化评估集（设计方案）

按 UI、技能、剧情、付费说明与客服分层抽样，保留文本键、上下文、字符约束、占位符、术语表、语言与版本。训练、提示调优与最终评测按内容或版本隔离，避免近似句泄漏。

| 类别 | 可复核问题 | 自动与人工分工 |
| --- | --- | --- |
| 准确性 | 漏译、否定关系、数值效果错误 | 规则发现候选，人工核实语义 |
| 术语与风格 | 同一物品不一致、角色语气失配 | 术语匹配 + 角色上下文评审 |
| 功能性 | 占位符损坏、乱码、截断 | 确定性检查 + 实机 LQA |
| 玩家风险 | 购买条件误导、敏感内容 | 高严重度人工审查 |
| 体验 | 教程完成、误操作、求助 | 随机实验与定性反馈 |

可参考 MQM 的错误分类思路，但项目严重度、权重和计分方式需明示；不声称自定义加权分就是官方 MQM 标准分。两位评审独立标注、计算一致性、仲裁分歧，记录修改后的规则。

LLM-as-judge 存在位置、长度、语言和自偏好问题。盲化来源、打乱 A/B 顺序，使用锚定样本和人工校准；拒答与无效输出单列，不当作满分。不要把一个模型的判断包装成客观真值。

## NPC、客服与分析助手

评估剧情设定一致、任务状态正确、提示注入抵抗、隐私泄露、拒答与恢复、检索依据及安全边界。把长会话、低资源语言、恶意文本与检索失败纳入回归集。

运营同时记录 p50/p95 延迟、每次成功交互成本、缓存命中、失败率、降级比例与人工接管。离线分数提高后仍需灰度；玩家输入默认不自动成为训练数据。

## Steam 平台事实

当前 Steamworks Content Survey 区分预生成和运行时生成内容，关注随产品交付、被玩家消费的 AI 内容，包含本地化；单纯提升开发效率的工具不是该部分的重点。实时生成还需说明防止违法内容的 guardrails。[S9](sources.md)

这不代表填写披露即可发布任意内容，也不代表使用辅助编程必然触发同一披露规则。具体提交时重新阅读官方问卷和发布要求。

## 可扩展交付物

在仓库三个已运行案例之外，可增加「50–100 条获准公开的多语言游戏文本→规则检查→双盲人工评审→错误分布→版本回归」项目。数据权限与上下文优先于样本量，不将 NDA 文本、未授权截图或玩家聊天上传公开仓库。
