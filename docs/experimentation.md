# A/B 测试与因果推断

实验前写清「对谁、改什么、预期改变哪个结果、什么情况下停止」。不要事后挑一个显著指标作为成功证据。

## 一页实验方案

| 项目 | 教程文案实验示例 |
| --- | --- |
| 假设 | 更清楚的教程提示提升安装当天完成率 |
| 实验单位 | 账号；跨端保持同一分组 |
| 资格 | 新安装用户，排除项在随机前定义 |
| 主要指标 | 全部分组用户中 D0 教程完成比例 |
| 护栏 | 崩溃、D7 留存、投诉与无障碍体验 |
| 分配 | 50:50，固定配置和实验 ID |
| 周期 | 事先固定样本量/周期，覆盖完整周与标签成熟 |
| 判定 | SRM/埋点质量通过，再看区间、最小收益和护栏 |

记录 assignment 与 exposure。Intent-to-treat 使用所有分配用户，可避免只分析接触后点击者带来的选择偏差；triggered 分析必须证明触发条件不受处理本身影响。

## 样本量与解释

预设基线转化率 p、绝对最小可检测差异 δ、显著性 α 和检验功效。等大两组、二元指标的粗略估计：

```text
n_per_arm ≈ 2 × (z_(1-α/2) + z_power)^2 × p(1-p) / δ²
```

例如 p=0.6、δ=0.03、α=0.05、功效 80%，约需每组 4,182 人。只是计划近似，聚类、重复观察、流失和多重比较会改变要求。默认 1,200 人教学数据不保证能检出设计中的 3.5 个百分点差异。

「增加 3 个百分点」和「相对提升 5%」在基线 60% 时是同一变化；必须标明绝对/相对。p 值不是原假设为真的概率，也不是商业收益概率。

## SRM 先于效果

Sample Ratio Mismatch 检查观察分组人数是否偏离预设比例。先调查分组服务、资格过滤、日志丢失、跨端重复、机器人过滤等原因，不能看到显著提升就忽略 SRM。[S5](sources.md)

仓库固定 50:50，用 χ²(1) 与 `erfc` 计算 SRM p；阈值 0.001 是本项目预设，不是通用规范。报告 `valid_allocation` 不等于整个实验已有效；还需检查日志、串组与干扰。

## 代码适用范围

[`experiment()`](../gamedatalab/analytics.py) 实现二元独立用户终点的 pooled z 检验与差值 Wald 95% 区间。任一组成功或失败少于 5 时拒绝输出，需精确方法或更多样本。收入长尾、配对设计、簇随机、非 50:50、序贯实验不能直接套用。

每天反复查看并在显著时停止会增加假阳性。可采用预定固定终点，或事先选定有效的序贯方法。多指标与多变体须控制多重比较；CUPED 只用处理前协变量，并检查其假设。

## 游戏中的干扰与替代设计

公会和匹配池可能存在处理溢出；按公会/服务器随机、switchback 或地理实验需另行分析相关性与时间趋势。无随机条件时可探索双重差分/断点，但必须说明平行趋势、选择与外部冲击，不能从普通前后对比推断因果。
