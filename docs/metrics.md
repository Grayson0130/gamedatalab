# 指标字典与时间口径

任何报表必须同时说明实体、窗口、时区、过滤条件和版本。本仓库统一 UTC、合成玩家 user_id、事件日和分析截止日；真实系统还应保留带时区时间戳与 ingestion_time。

| 指标 | 定义 | 常见错误 |
| --- | --- | --- |
| DAU | 当日有有效 session 的去重 user_id | 用事件数当人数 |
| WAU/MAU | 固定说明滚动 7/30 日或自然周/月 | 把两种窗口混比 |
| Dn retention | D0 新增在恰好 Dn 有 session / D0 新增 | 未成熟视为 0 |
| Payer conversion | 同窗口去重付费人数 / 明确的玩家分母 | 与交易成功率混用 |
| ARPDAU | 当日收入口径 / DAU | 换成当日新增人数 |
| ARPPU | 同窗口收入 / 同窗口付费人数 | 不说明零付费日 |
| D0–DH LTV | 成熟安装队列累计净额 / 原始新增人数 | 用幸存者作分母 |
| CAC | 定义成本 / 对应新增人数 | 漏素材费和归因重叠 |
| ROAS | 同队列窗口收入或贡献额 / 投放费 | 混用毛收入和净贡献 |
| Churn label | 本例 D7–D13 无 session | 当成永久退出 |
| Tutorial completion | 安装当天完成者 / 当天可完整观察的分组用户 | 只分析完成教程的人 |

## 时间线实例

2026-09-01 安装：D0=9 月 1 日、D6=9 月 7 日、D7=9 月 8 日、D13=9 月 14 日、D30=10 月 1 日。
截至 9 月 30 日，D7 可观察，D30 不可观察；D30 留存和收入不得当作 0。日历日口径不保留安装时刻；生产若要求精准经过小时需改成时间戳计算。

## 金额实例

一名玩家充值 10 美元、退回 2 美元，净交易额 8 美元；假定平台费为净额的 30%，则简化贡献为 5.6 美元。获客费 2 美元时贡献 ROAS=2.8。它仍未扣服务器和税费，不能命名为利润 ROAS。

本例退款在原交易当天生成以简化教学；跨日/跨月退款的发生期口径、订单重述口径必须在真实财务模型中分别处理。负净收入不能简单截为零。

## 指标验收

1. 用包含零活动、重复事件、退款和最新安装的手算样本对齐 SQL。
2. 检查每个事件粒度与 join 基数，先按用户聚合避免订单×session 放大。
3. 比较分组和总量，但不简单平均各队列比率；应按对应分母加权。
4. 新版本灰度期间，按客户端版本观察上报率与空值率，不能将漏报当留存下降。
5. 报告同时给出人数与窗口；对小样本比例给区间，对长尾收入用适当 bootstrap。
