# 游戏推荐系统：先定义推荐对象

商店游戏发现、关卡推荐、UGC 内容排序、道具推荐和对战匹配有不同目标。对战匹配还涉及技能公平、延迟和排队时间，不能直接当作点击率推荐。

## 从可解释基线开始（本章为设计文档）

1. 约束过滤：地区可用、年龄、设备兼容、已拥有、语言与内容偏好。
2. 热门/新鲜度基线：分地区与类别，避免全站头部占满。
3. 基于内容：题材、标签、语言、玩法与合法可用的文本嵌入，服务冷启动。
4. 协同过滤：隐式行为的 item-item 或矩阵分解；缺少交互不等于明确不喜欢。
5. 数据足够后比较双塔召回、学习排序、多模态模型；复杂性必须带来可测收益。

Item-based 不总比 user-based 计算量小，取决于用户/物品规模、稀疏度和索引方式。图数据库是数据存储选项，图神经网络是模型，两者互不等价。

## 数据与时间切分

记录曝光、位置、候选集版本、点击、有效游玩和负反馈。没有曝光日志时，不能把未见过的物品全当负样本。

训练使用截止 T 之前的交互；验证/测试使用 T 之后的首次相关行为。构造物品热度、标签和嵌入时也要遵守时间边界，避免发布后的信息泄漏。按用户留最后一条若混入其他用户未来交互，仍可能存在全局时间泄漏。

离线固定候选全集或明示负采样方法；采样 NDCG 不能直接比较不同候选规模的实验。

| 阶段 | 指标 | 必须补充 |
| --- | --- | --- |
| 召回 | Recall@K | 候选数、冷启动覆盖 |
| 排序 | NDCG@K、MRR | 相关性定义、负采样策略 |
| 生态 | 覆盖率、多样性、长尾曝光 | 创作者与语言分布 |
| 在线 | 有效游玩、长期回访 | 退款、负反馈、延迟与成本 |

## LLM、Bandit 与上线

LLM 可用于查询理解、内容标签和推荐解释，输出须从可用目录检索并验证，避免虚构游戏。不得把用户自由文本当可执行指令或数据库权限。固定热门/内容基线未被击败前，没有理由先部署大模型。

Bandit 是探索与利用的在线分配问题，需记录 propensity 并检查支持覆盖；离线反事实估计不代替随机实验。强化学习可能受延迟奖励与策略反馈影响，不能因为是 2026 年就默认必要。

灰度流程：离线回放→影子流量→小流量随机实验→长期护栏→回退。策略适用于商店推荐，不用于以高付费潜力扭曲竞技匹配。

本仓库暂未实现推荐训练与服务，避免将文档中的方案混为完成品。可先扩展一个有时间切分和曝光日志的内容推荐项目。
