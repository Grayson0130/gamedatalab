# 留存、流失与欺诈：三个不同的问题

留存描述回访，流失模型预测未来不活跃，欺诈识别恶意行为。不能因为玩家低频或不付费就判定作弊，也不能把一次缺席定义成永久退出。

## 留存口径

- **Exact-day**：D0 新玩家在恰好第 N 日有有效活动；D1、D7、D30。
- **Rolling**：第 N 日或以后回访，必须额外固定最后观察日，否则不同队列不可比。
- **Bracket**：例如 D7–D13 任一天活跃，适合周频游戏。
- **Resurrection**：历史不活跃后回归，与新客留存分开统计。

一个人在一天内多个 session 只算一个活跃用户；收入事件本身不自动代表有效游玩。日历日口径与安装后 24 小时窗口不同。新队列观察不完整时显示 NULL，而非 0。队列按语言、平台或版本细分前报告人数，防止小样本和辛普森悖论。

## 流失预测的时间合同

本仓库规定：D0–D6 提取早期活跃天数；D7 开始预测；D7–D13 无 session 则标签为 1。只有完整看到 D13 的玩家能生成标签。这个标签描述「下一周不活跃」，不是永久流失。

训练安装日不晚于 2026-08-10；测试安装日不早于 2026-08-18；中间七天安装队列作为隔离带。最晚训练标签在 8 月 23 日结束，最早测试预测在 8 月 25 日开始，避免训练时看到测试预测时点之后的标签。[代码](../gamedatalab/analytics.py)

基线按 D0–D6 活跃天数分桶，用 `(流失人数+1)/(桶人数+2)` 平滑，未知桶回退到训练先验。它简单、可解释、只依赖标准库，不声称胜过树模型或序列模型。

## 评估与行动

报告基准流失率、ROC AUC、PR AUC（扩展项）、Brier/校准、预算约束下 precision@K。对新队列和关键语言单独评估。预处理只用训练集；未来充值、未来最后登录和全窗口统计不能进入特征。[S6](sources.md)

高风险不等于可挽回：有些人无论是否优惠都会回来，另一些不会被优惠改变。优惠策略应通过随机留出或 uplift 方法估计增量贡献，计入奖励成本、疲劳与价格公平性。不能默认免费订阅或折扣是最佳干预。

## 欺诈与反作弊的独立流程（设计方案）

| 场景 | 可用证据 | 误判风险 |
| --- | --- | --- |
| 支付欺诈 | 服务端订单校验、拒付、交易速度 | 共享支付方式、旅行 |
| Bot/刷量 | 服务端操作间隔、任务路径、账户关联 | 无障碍辅助、重复练习 |
| 对战作弊 | 权威服务器状态、不可能动作、回放 | 高水平玩家、延迟 |
| 经济滥用 | 道具流水、闭环转账、异常套利 | 正常公会交易 |

先建设规则、案件标注和人工复核，再比较异常模型或图特征。设备指纹不是默认合规的数据源；关联图也可能混入共享设备。使用延迟确认标签进行时间回放，报告每万正常玩家误伤数、审核负载、申诉翻案率与检测延迟。

低置信度先观察或进入复核队列，高影响封禁需充分证据和申诉途径。仓库未实现风控引擎或封号自动化。
