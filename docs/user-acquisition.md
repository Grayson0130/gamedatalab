# 用户获取：从归因报表到增量收益

不要先问「哪个渠道 CPI 最便宜」，先问「投放带来多少本来不会发生的新增与贡献利润」。归因、预测和因果估计回答不同问题。

## 业务模型决定漏斗

| 产品 | 建议漏斗 | 主要混淆 |
| --- | --- | --- |
| 免费移动游戏 | 曝光→商店→首次启动→教程→D7 活跃→付费 | 下载不等于启动；重复安装不等于新玩家 |
| PC 买断 | 商店访问→愿望单→购买→首次启动→退款后保留 | 愿望单不等于销售；促销、地区价格变化 |
| 跨端服务型游戏 | 曝光→账号创建→有效游玩→跨端回流 | 多设备及游客转正后重复计数 |

明确新客定义、归因窗口、点击/展示优先级、UTC 截止时间、平台和自然量规则。转化率分母是有机会完成下一步的人，不能混用全部曝光和已授权子集。

## 三层测量

1. **平台归因**：说明平台规则下给谁记功。不能把多平台报表相加当唯一新增。
2. **队列经济性**：按首次安装日×渠道跟踪相同年龄留存、净收入、回本。未成熟 D30 单列。
3. **增量实验**：可行时在地区或用户群设随机留出，估计投放相对不投放的增量。地理实验需处理地区差异、溢出和功效。

`CPI = spend / attributed_installs`；`incremental_CAC = incremental_spend / incremental_new_users`。增量新增接近零时，比率极不稳定，应报告区间。

## 2026 归因更新

Google 官方状态页（2026-08-14 更新）将 Chrome/Android Attribution Reporting、Topics、Protected Audience 等列为弃用移除，CHIPS 等则继续支持。不能泛化为所有隐私能力取消，也不能将上述广告 API 作为新项目默认依赖。[S1](sources.md)

Apple AdAttributionKit 更新记录包含再参与测量能力；须核对目标 OS、广告网络及 SDK。匿名、延迟且可能缺失字段的 postback 不等于完整逐用户路径。[S2](sources.md)

## MMM、MTA 与小样本

MMM 是聚合时间序列建模，需控制季节、价格、促销和媒体共线性，用实验校准。将支出直接放进回归不能自动得到因果预算分配。MTA 依赖可观测接触路径，跨设备和授权缺失可造成系统偏差。小团队历史不足时，先做成熟渠道队列表和留出实验。

创作者合作记录内容成本、时间、专属链接/码、地区和自然传播重叠；优惠码可能被转载。邮件打开率受客户端代理影响，重点追踪有同意基础的有效到站和实际转化。

## 可执行分析

运行 `python -m gamedatalab`，查看 `reports/demo/summary.json` 的 `ltv`。每玩家成本是人为分配的合成支出，并未实现真实广告归因。

决策前检查：差异来自地区、设备还是版本？队列是否同龄？是否覆盖退款和创意制作费？自然量是否被归给付费渠道？提升能否在留出实验复现？
